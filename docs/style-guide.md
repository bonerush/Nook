# 写作规范

## 目的

本规范约束 Nook 文档的写法。

目标有三点：

1. 新手能一次读懂。
2. 句子可检查。
3. 多篇文档用词一致。

## 合规说明

本规范参考 ASD-STE100 Issue 9 的结构。

我们不声称通过官方认证。

ASD 不认证文档，也不认可任何“完全合规”的工具。

我们用可检查的规则约束写作。

## 十条规则

### 规则 1：一句一个意思

反例：

> 保存设置后关闭窗口，然后重新开始并检查面板是否出现。

正例：

> 保存设置。
> 关闭窗口。
> 重新开始。
> 检查面板。

### 规则 2：操作句不超过 20 个汉字

操作句描述用户动作。

超过 20 个汉字时，拆成两句。

### 规则 3：说明句不超过 25 个汉字

说明句解释概念。

超过 25 个汉字时，先写结论，再写原因。

### 规则 4：一段不超过 6 句

段落只讲一个主题。

主题变化时，另起一段。

### 规则 5：步骤以动词开头

反例：

> 窗口的关闭由用户完成。

正例：

> 关闭窗口。

### 规则 6：使用主动语态

反例：

> 计划会被校验器修复。

正例：

> 校验器修复计划。

### 规则 7：禁用分号

分号表示两个意思挤在一句。

拆成两句。

### 规则 8：禁用“进行、予以、加以 + 名词”

反例：

> 对配置进行校验。

正例：

> 校验配置。

### 规则 9：术语只用一个译名

| 概念 | 固定写法 | 禁止写法 |
| --- | --- | --- |
| script | 讲稿 | 稿件、文本、台词 |
| token | 词元 | 标记、单词块 |
| phrase plan | 断句计划 | 分组方案、断句结果 |
| breath line | 呼吸行 | 提词行、歌词行 |
| prompt document | 提词文档 | 播放文档、文档 |
| panel | 提词面板 | 悬浮窗、窗口 |
| editor | 编辑窗口 | 主窗口、编辑器 |
| cache | 缓存 | 暂存、快取 |

代码标识符保持英文。

### 规则 10：图表必须独立可读

每张图必须有：

- 标题。
- alt 文本。
- 一句说明。
- 导出后的 PNG。

图中文字不得重叠。

## 数字与单位

- 快捷键写作 ⌘↩、⌃⌥Space。
- 数字与单位之间加空格，例如 60 秒。
- 版本号写 2.0.0。

## 文档结构

每篇文档按顺序包含：

1. 标题。
2. 读完能做什么。
3. 正文。
4. 下一步。

操作文档还要有前置条件。

## 检查清单

- [ ] 标题只有一个一级标题。
- [ ] 开头写了“读完能做什么”。
- [ ] 操作步骤以动词开头。
- [ ] 没有分号。
- [ ] 没有“进行 + 名词”。
- [ ] 术语与术语表一致。
- [ ] 图片有 alt 文本。
- [ ] 链接可打开。
- [ ] 结尾有“下一步”。

## 自动检查

运行：

~~~bash
./scripts/check-docs.py
~~~

脚本检查七项：

1. 句子长度。
2. 段落句数。
3. 分号与禁用词。
4. 术语变体。
5. 相对链接。
6. 图片文件与 alt 文本。
7. 标题结构。

脚本给出 0 到 100 分。

低于 80 分时返回非零退出码。

脚本是代理指标。

它不判断主动语态。
它不判断一句一指令。
它不判断图表文字重叠。

这些项由人工审查。

## 例外

以下内容不受句长限制：

- 代码块。
- 表格。
- 命令行。
- 快捷键列表。
- 引用块中的错误原文。

## 维护

新增术语时，先更新本页术语表。

新增文档时，更新 docs/README.md 的路线表。
