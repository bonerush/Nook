## Blockers（必须修）

### B1. 960 宽（实际最小窗口）下纸张最后一行被底部渐变与分隔线“切掉”
- 证据：`docs/assets/editor-compact.png` 与我自行采集的 960×712 实拍中，最后一段第二行 `I can contribute.` 只剩上半截，下行字身被纸张底部 16 pt 白色渐变淡出，紧接着是呼吸图上方 0.5 pt 分隔线（y=580.5，最后一行可见像素止于 y=566）。视觉上等同“文字被分隔线切断”。
- 位置：`Sources/Nook/Editor/ScriptPaper.swift:96-117`（`editorArea` 的 `.overlay(alignment:.bottom)` 渐变，高 16）与 `ScriptPaper.swift:26-34`（呼吸图固定占位）。文本区高度随窗口收缩，但底部渐变与固定高度呼吸图不预留“半行/整行”空间。
- 影响：违反 spec 第 8 节验收“960×680 与 1080×740 无裁切、无重叠”。这是最小窗口的自然打开态，不是需要滚动才出现的边缘情况。
- 建议：为文本区底部预留一行行高（或让渐变区高度 ≥ 行高，或滚动时把最后一行滚入完整行）；同时给 `NSTextView` 底部 contentInsets 增加行高余量；分界线与文字之间至少留 8 pt。

### B2. AI 处理中使用无限旋转的 ProgressView，违反动效规范且不随 Reduce Motion 停止
- 证据（代码）：`EditorToolbar.swift:84`（Start → Phrasing… 的 spinner）、`EditorToolbar.swift:128`（AI 状态胶囊 busy）、`AISettingsOverlay.swift:301`（Test connection）、`NookComponents.swift:65`（NookChip busy）。均为 `ProgressView()` 无限循环。
- 违反：spec 5.7 明确“不使用无限旋转加载器；planning 用脉冲点 + 文案”；同节写“AI planning 循环脉冲 1.4 s / 状态点 opacity 0.45↔1”。`AIStatusChip` 已声明 `@Environment(\.accessibilityReduceMotion)`（`EditorToolbar.swift:107`）却未使用，spinner 在 Reduce Motion 下仍持续旋转。
- 建议：改为规范中的脉冲状态点（读取 reduceMotion，开启时静态点 + 文案），删除 4 处 ProgressView；Test connection 用同样的 pulse 或短 fade。

## Non-blocking（建议，按优先级）

1. **全界面缺少 hover 反馈**：`Sources/Nook` 内除提词面板的鼠标位置轮询外没有任何 `onHover`；`NookIconButtonStyle/NookSecondaryButtonStyle` 只有按下态。spec 5.7 规定 hover `.smooth(0.16)` 背景 surfaceMuted、图标亮度 +4%。工具栏两个图标按钮、检查器折叠头、AI 表单的 provider 按钮都无悬停提示。
2. **检查器三条滑块不一致**：Pace 行滑块无刻度、轨道比另两条短约 36 pt（`InspectorPane.swift:145-163` 值标签内联在同一 HStack）；Type size / Panel width 用 `sliderRow`，macOS 为 step 滑块绘制 1 px 刻度虚线（`InspectorPane.swift:205-229`）。同一张卡片内轨道右端不对齐、刻度有无不同。建议统一为“标签行 + 全宽滑块 + 右侧数值”。
3. **分段控件在自定义 WPM 下丢失选中态**：`PaceSegmentedControl.swift:19-21` 用 `Int(round)==preset.wpm` 精确匹配，滑块拖到 138 以外时 `selectedIndex == nil`，没有任何胶囊被选中。建议改为最近预设或保留上一次选择。
4. **两处对比度不达标**：AI 表单选中的 Provider 文案用 accent `#007AFF` 落在 accentSoft（`#E6F2FF`）上约 3.5:1（10.5 pt 需 4.5:1，`AISettingsOverlay.swift:116-143`）；BreathRibbon 色块为 accent 42% ≈1.85:1 对白纸（信息性图形需 3:1，`BreathRibbon.swift:64-84`）。提词面板非活跃歌词行 0.32/0.20 白色透明度在深玻璃上远低于大字号 3:1，属 Apple Music 式设计，但发布会读稿时下两行几乎不可读，建议提到 0.45/0.28。
5. **焦点可见性与 960×680 验收尺寸不可达**：AI 表单输入框为 `.textFieldStyle(.plain)` + 自绘边框（`AISettingsOverlay.swift:378-396`），实拍中键盘焦点无可见焦点环/光标；`FirstSettingsFieldFocusBridge` 只把焦点放到 Base URL。另：`window.contentMinSize = 960×680` 叠加全出血标题栏后，`setContentSize(960,680)` 实际得到 960×712 帧（实测 `--preview-compact` 窗口 960×712），因此 spec 验收的 960×680 状态无法复现；建议把 minSize 显式校正为 960×680 内容区或把验收改为 960×712。

## Notes

- **层次与材质**：画布 #F5F5F7→#FAFAFC + 白纸 + 0.5 pt 描边 + 5% 阴影，纸张/检查器/工具栏层次清楚；工具栏 material 与画布区分正确；无第二强调色，符合“一个强调色、两种材质、三种圆角”。
- **间距/圆角**：纸张圆角 20、检查器 12、控件 8/9；纸张内边距 36/26，正文起点与标题左缘相差约 1.5 pt（可接受）。
- **字体层级**：display 28 / title 17 / callout 13 / caption 11 / micro 10 / mono 10.5，层级成立；但正文行宽：1080 下首行约 82 字符（超过 spec 的 64–72），960 下约 55–60 字符（低于区间），documented 的 720 pt 纸宽与 64–72 字符目标互相冲突。建议纸宽或字号二选一调整。
- **检查器与纸张高度**：两者均为 `maxHeight: .infinity`，实拍等高（701/673），无底部错位。960 下检查器内容未溢出，但滚动指示器被隐藏（`showsIndicators:false`），长内容无滚动提示。
- **空状态**：图标 + 标题 + 两行说明 + Load sample，居中稳定，960 宽不裁切；图标 `phaseAnimator` 2.8 s 无限往返属 spec 5.7 明确允许项，Reduce Motion 下静止。空稿时仍显示 “0 words · 0 sentences · English · line breaks” 与 0:00 徽标，信息略冗余但不误导。
- **Ai 设置面板**：580 宽卡片、22/20/60 三档留白稳定；1080/960 均可完整显示；footer “Clear key ← … Test connection / Cancel / Save（默认动作）”顺序与 HIG 一致。API key 行眼睛按钮在字段外，导致该行字段比 Base URL/Model 短约 57 px、右缘不对齐；剩余空间在提示行与 footer 之间偏大。spec 要求的是 material 面板，实际为不透明白卡（可接受，但未按 spec）。
- **动效克制度**：入场 0.5 s（opacity + y+8）、检查器 0.3 s、分段 0.22 s、按压 0.18 s、面板入场 0.32 s（reduce motion 时 0.12 s 仅淡入）、提词面板歌词 spring 0.56；无夸张曲线。`NookMotion.resolved` 统一把位移换成 0.01 s（spec 写 easeOut，实现为 linear，无实质差异）。
- **Reduce Motion 覆盖**：入场、检查器展开、分段选择、呼吸带、空状态图标、歌词、提词面板入场均读取；遗漏：状态栏/纸张/检查器数值的 `.animation(NookMotion.counter)` 未经过 resolved（numericText 仍滚动）；`NookIconButtonStyle` 按压动画未读；B2 的 spinner；`TeleprompterController.reposition/applyFrame` 的 0.22 s 窗口移动未读。plan 要求的 `accessibilityDisplayOptionsDidChangeNotification` 订阅未实现（只在 show/hide 时读取一次，行为上可接受）。
- **可访问性标签**：工具栏图标、检查器折叠头、分段按钮、滑块、眼睛按钮、关闭按钮均有 label/help；呼吸图有 “Breath map. N sentences. About X seconds.” 摘要；歌词有 “Reading line X of Y”；进度轨有 elapsed/remaining。状态栏 keycap（⌘↩、⌃⌥Space）会被读作符号，未提供更可读的替代文本。
- **细节**：插入光标为系统蓝，符合强调色；鼠标穿透保留（panel `ignoresMouseEvents=true` + 全局悬停轮询）；滚动条在编辑器与检查器全部隐藏（安静但无滚动提示）；“Best-effort capture hiding / Asks capture tools to skip the panel. Some meeting apps ignore this.” 文案与 spec 5.11 一致；实测 `hideFromCapture` 开启时 `screencapture` 确实无法捕获提词面板（需 `NOOK_CAPTURE_VISIBLE=1` 才能截到），与“尽力而为”的措辞相符。
- **提词面板**：680×205 固定、圆角 30、单一玻璃表面 + 深色 scrim 共用裁切；当前行白色、上下各一行淡出（mask 0.13/0.90）；进度轨 2 pt + 5 pt 白点（带蓝色 glow 阴影，属 spec“不使用彩色阴影”的小偏差）；底部 9.5 pt / 白 76% 的 “0:15 · LOCAL · 138 WPM · −0:44” 清晰；READY/PAUSED/DONE 状态后缀随 phase 出现。
- **未完成的检查**（如实声明）：未做真实键鼠 Tab 焦点顺序走查（无 AX 权限）；未切换系统 Reduce Motion 实测（仅代码核对）；未测试 fontSize=38 / cardWidth=860 的提词面板横向溢出；`--preview-no-inspector` 的 1080 与 960 截图已采集（`/tmp/ui-noinspector.png`、`/tmp/ui-noinspector-compact.png`）但未逐项目检；未查看 AI 表单在 DeepSeek/推理分区展开时的高度与溢出。

## 剩余 non-blocking（最多 5 条）

1. **960 宽下最后可见行仍落在底部 7% 渐变里**：实测该行自上而下最暗像素 52→144（≈80%→44% 黑），即基线附近约 50% 透明，字母下半截发灰。未被切断、无重叠，但观感像“半透明行”。建议把渐变起点从 93% 下移（或渐变高度 ≤20 pt / 仅内容溢出时启用）。
2. **全编辑器仍无 hover 反馈**：`grep onHover` 仅命中提词面板轮询；工具栏、检查器折叠头、AI 表单按钮仍只有按下态（spec 5.7 hover `.smooth(0.16)`）。

4. **planning 期间三个动画同时进行**：新增 `PlanningActivityLine`（1.15 s 线性无限扫过，`EditorToolbar.swift:47`）+ Start 脉冲点 + 状态胶囊脉冲点，超过 spec 5.7“同一时刻最多两个元素移动”；Activity Line 亦不在 spec 动效表内（Reduce Motion 下已正确降级为静态段）。
5. **960×680 验收尺寸仍不可达 / 行宽超规范**：`contentMinSize 960×680` 叠加全出血标题栏后 `setContentSize(960,680)` 实测仍为 960×712（与 `docs/assets/editor-compact.png` 一致），spec 第 8 节的 960×680 未被真正覆盖；1080 下正文首行约 82 字符，仍高于 spec 的 64–72。
